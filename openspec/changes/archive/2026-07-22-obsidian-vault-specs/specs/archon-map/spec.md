# archon-map Specification

## Purpose

The `archon-map` capability is a deterministic Go module (`internal/mapgen`) and
`archon map` CLI subcommand that regenerates `openspec/map.md` (capabilities index +
materialized backlink map), rewrites boundary-crossing relative links on archive, offers
a `--check` guard, and supports a one-shot `--backfill` mode for existing archived changes.

## Requirements

### Requirement: map.md Generation

`archon map` MUST regenerate `openspec/map.md` by walking `openspec/`, writing a
capabilities index, an active-changes index (phase and status read from `state.yaml`),
an archive index grouped by date, and a per-capability backlink section listing the
changes that reference each capability. All generated content MUST be written exclusively
inside the `<!-- MAP:START -->` … `<!-- MAP:END -->` managed region. Output ordering MUST
be deterministic (capabilities alphabetical, active changes by name, archive by date desc).

#### Scenario: map.md index sections are generated

```gherkin
@happy
Scenario: map.md index sections are generated
  Given an openspec/ tree with two capabilities and one active change
  When archon map is run
  Then map.md contains a capabilities index listing both capabilities
  And an active-changes index listing the active change with its phase and status
  And an archive index (empty if no archived changes)
  And a backlink section associating each capability with changes that reference it
```

#### Scenario: Generation is deterministic and idempotent

```gherkin
@happy
Scenario: Generation is deterministic and idempotent
  Given openspec/map.md generated by a first run of archon map
  When archon map is run a second time without any file changes
  Then the resulting map.md is byte-identical to the first run output
```

#### Scenario: Active change phase and status come from state.yaml

```gherkin
@happy
Scenario: Active change phase and status come from state.yaml
  Given changes/my-feature/state.yaml with phase: design and status: in_progress
  When archon map is run
  Then the active-changes index shows my-feature with phase=design and status=in_progress
```

### Requirement: Managed-Region Integrity

`archon map` MUST write ONLY between `<!-- MAP:START -->` and `<!-- MAP:END -->`.
Content outside the managed region MUST be preserved byte-for-byte. If `map.md` does
not exist, the tool MUST create it with a minimal preamble and the managed region.
If `map.md` has no managed-region markers, the tool MUST append the markers and
regenerate without modifying any existing content.

#### Scenario: Existing prose outside markers is preserved

```gherkin
@happy
Scenario: Existing prose outside markers is preserved
  Given openspec/map.md with authored prose before and after the managed region
  When archon map is run
  Then prose outside the markers is byte-identical to before
  And only content inside the markers is replaced
```

#### Scenario: map.md created when absent

```gherkin
@edge
Scenario: map.md created when absent
  Given openspec/ exists but map.md does not
  When archon map is run
  Then openspec/map.md is created
  And it contains a managed region with the generated index and backlinks
```

### Requirement: --check Mode

`archon map --check` MUST exit non-zero if any managed region in `openspec/` is stale
(differs from what a fresh run would produce) or if any relative markdown link inside
`openspec/` resolves to a missing file. It MUST NOT modify any file. It MUST emit a
human-readable report identifying each stale region or dangling link.

#### Scenario: Check passes when map.md is up to date

```gherkin
@happy
Scenario: Check passes when map.md is up to date
  Given openspec/map.md freshly generated and no dangling relative links
  When archon map --check is run
  Then the command exits zero
  And no errors are reported
```

#### Scenario: Check fails on stale managed region

```gherkin
@error
Scenario: Check fails on stale managed region
  Given openspec/map.md whose managed region does not match a fresh generation
  When archon map --check is run
  Then the command exits non-zero
  And the output identifies the stale managed region
  And no files are modified
```

#### Scenario: Check fails on dangling relative link

```gherkin
@error
Scenario: Check fails on dangling relative link
  Given an openspec artifact containing a relative link to a file that does not exist
  When archon map --check is run
  Then the command exits non-zero
  And the output identifies the dangling link and the source file
  And no files are modified
```

### Requirement: Archive Link Rewriting

When invoked as part of the archive move (`changes/{c}/` →
`changes/archive/YYYY-MM-DD-{c}/`), `archon map` MUST deterministically rewrite the
boundary-crossing relative links: (a) links in `map.md` that pointed to the old change
path, and (b) relative links inside the moved files that pointed outward to `specs/`
(which shift one directory level after the move). Wikilinks MUST NOT be rewritten.

#### Scenario: map.md link to change is updated after archive move

```gherkin
@happy
Scenario: map.md link to change is updated after archive move
  Given map.md containing a relative link to changes/my-feature/proposal.md
  When sdd-archive moves my-feature to changes/archive/2026-07-22-my-feature/
  Then map.md is updated to link to changes/archive/2026-07-22-my-feature/proposal.md
  And no other links in map.md are modified
```

#### Scenario: Intra-change relative links to specs/ are rewritten after move

```gherkin
@happy
Scenario: Intra-change relative links to specs/ are rewritten after move
  Given a change artifact containing a relative link ../../../specs/foo/spec.md
  When the change is moved one directory deeper into the archive
  Then the relative link is rewritten to ../../../../specs/foo/spec.md
  And the link resolves to the same target file as before
```

#### Scenario: Wikilinks are not rewritten during archive

```gherkin
@happy
Scenario: Wikilinks are not rewritten during archive
  Given a change artifact containing [[harness-workflow]]
  When the change is archived
  Then the wikilink is not modified
```

### Requirement: --backfill Mode

`archon map --backfill` MUST perform a one-shot pass over all archived changes in
`openspec/changes/archive/` to rewrite boundary-crossing relative links and regenerate
`map.md`, producing a valid link graph for pre-vault artifacts. The default (no flag)
MUST be forward-only: only changes created after vault adoption are processed.
`--backfill` MUST be idempotent: running it twice produces no diff.

#### Scenario: Backfill rewrites links in existing archived changes

```gherkin
@happy
Scenario: Backfill rewrites links in existing archived changes
  Given archived changes containing relative links that cross the archive boundary
  When archon map --backfill is run
  Then all boundary-crossing relative links in archived changes are rewritten
  And archon map --check passes after backfill completes
```

#### Scenario: Backfill is idempotent

```gherkin
@happy
Scenario: Backfill is idempotent
  Given archived changes already processed by a first --backfill run
  When archon map --backfill is run a second time
  Then no files are modified (output is identical to the prior run)
```

#### Scenario: Default run does not touch archived changes

```gherkin
@edge
Scenario: Default run does not touch archived changes
  Given archived changes with stale links
  When archon map is run without --backfill
  Then no archived change files are modified
```
