# Proposal: Concise Chat Output Skill

## Intent

The ARCHON orchestrator's **chat replies to the user** are too long and verbose. We
want a persona-level reflex that keeps those replies short and direct — but
**selectively**, never at the cost of the review gates, decision content, or persona
language/tone rules. No such rule exists today; `detail_level`
(`skills/_shared/persistence-contract.md:158`) governs subagent artifact verbosity,
a different axis, and must not be conflated with this change.

## Scope

### In Scope
- NEW skill `skills/concise-output/SKILL.md` (comment-writer-style behavior skill,
  auto-embedded via the `skills/*/SKILL.md` glob; no registry edit needed).
- Persona section in `internal/initcmd/templates.go` (source of truth for CLAUDE.md).
- SURGICAL edit of the committed `CLAUDE.md` adding a short "Concise Chat Output" rule
  pointing at the skill (NO `archon init` regen).

### Out of Scope
- Subagent handoff prompts and `detail_level` — untouched.
- Any weakening of the Leader Persona (warm/direct, Spanish replies, tone) or the
  Human Review Gate / Vague Request Guard / Commit Attribution rules.
- Back-porting the template↔CLAUDE.md desync (Rule 2 / Phase Models hand-edits) —
  known follow-up, explicitly deferred.
- Hand-bumping `.archon/config.yaml` `skill_count` (24→25) / `skill_inventory` —
  regenerated by a later `archon update`.
- `skills/embed_test.go` expected-list extension — optional, low value; deferred.

## Capabilities

### New Capabilities
- `concise-output`: encodes the concise-by-default chat behavior for the
  orchestrator's user-facing replies, including the preserve-verbatim allow-list and
  the must-not-weaken constraints.

### Modified Capabilities
- None. No existing `openspec/specs/*` requirement changes; this adds orchestrator
  behavior, not a harness capability spec.

## Behavior the Skill Encodes

**Concise by default (chat only):** lead with the actionable point; prefer a tight
bullet list or 1–3 short paragraphs; drop narration, throat-clearing, and recap of
work the user can already see. Scope is the orchestrator's CHAT output to the user
ONLY.

**Preserve-verbatim allow-list (NEVER trim, always complete):**
- the Human Review Gate question `¿Quieres ajustar algo en esta fase antes de continuar?`
  (Spanish, quoted verbatim);
- decision tables (e.g., the preflight A–E options);
- risks and open-question lists;
- the substantive content of SDD artifacts shown to the user.

**Must-not-weaken constraints (defer to these on any conflict):**
- Leader Persona language rule (reply in the user's language; neutral Spanish);
- warm/direct tone;
- Human Review Gate SHOW+ASK contract, Vague Request Guard, Commit Attribution.

**Decision gate:** when unsure whether something is trimmable narration or
load-bearing content, KEEP it. "Concise" never overrides a gate or drops the allow-list.

## Approach

**Approach 3 (approved at explore gate — do not re-litigate).** The behavior is a
persona-level reflex, so a short persona pointer is needed for reliable activation;
the detailed contract lives in the skill to keep the always-loaded persona lean.

- **Activation:** passive reflex — an always-on behavior rule on the orchestrator's
  chat replies. NOT `user-invocable`; no slash command.
- **Skill body:** English (repo artifact default); the Spanish gate string quoted
  verbatim. comment-writer-style frontmatter (`name`, Trigger-first `description`,
  `license`, `metadata.version`) plus `disable-model-invocation` / non-invocable so it
  behaves as a passive persona reflex, not a user command.

### Expected shape of each edit surface

1. `skills/concise-output/SKILL.md` — frontmatter + body sections: When to Use (scope =
   orchestrator chat only), Hard Rules table (concise-by-default + preserve-verbatim
   allow-list), Must-Not-Weaken list, a "when in doubt, keep it" Decision Gate, short
   examples.
2. `internal/initcmd/templates.go` — a new "Concise Chat Output" persona subsection
   (2–4 lines) added to `orchestratorSections`, naming the skill and its preservation
   list; backticks written as `§` per the template convention (`templates.go:15,:195`).
3. `CLAUDE.md` — the SAME 2–4 line section inserted surgically near the Leader Persona,
   with literal backticks. Surgical only — a regen would revert PR-1's hand-edited
   Rule 2 (`CLAUDE.md:125`) and Phase Models (`:141-142`) sections.

## Rollback Plan

Revert the three edits: delete `skills/concise-output/SKILL.md`, remove the persona
subsection from `templates.go`, and revert the surgical `CLAUDE.md` insertion. No
data, no migrations, no runtime state; a single-commit revert restores prior behavior.
